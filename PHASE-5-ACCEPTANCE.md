# Phase 5 Remote Image / Character Localization acceptance candidate

Status: code-side candidate. The initial Remote Routing Gate was reported working on the real SillyTavern 1.19.0 host, but the newer Character Localization and the combinations below have **not** received installed-host acceptance. Keep both `stage/phase-5-remote-image` branches separate from `main`; do the Release Closeout only after the user records the installed-host result. No Allowlist Manager, Audio/Video, or full Media Manager is in this phase.

## Contract and automated evidence

| Area | Candidate behavior / automated evidence |
| --- | --- |
| Remote routing | `AFTER_MARKDOWN` removes remote `src`, `srcset` and `picture/source` request paths before insertion, then hydrates asynchronously through Server Network. The browser does not silently request the source; failures provide a visible error and an explicit direct-source link. The Routing switch is stored only in the current browser and applies to subsequently rendered chat images. It is off by default. |
| GIF | Remote and localized Original are delivered as GIF Blob bytes and displayed by an Object URL. Object URLs are released after removal/teardown; moved live nodes retain them. There is no transform to a static preview in this route. |
| Streaming | A partial reply's aborted request cannot install a late result over a final rendered image. Removed nodes abort and release; a live node moved within the document remains usable. |
| Binding lifecycle | A user-private Catalog binds `(Character Scope, SHA-256 remote Locator)` to an immutable MediaRef. Localize imports through the existing policy-controlled Network and Media modules before revision CAS. An unsuccessful import or stale CAS leaves the previous Binding; a successful update replaces its reference without deleting old Media. Localize/update/unlocalize refresh all live images of the same host and URL. Two independent Server clients using the same ST user root observe the same Catalog. |
| Identity / detached | Ordinary ST atomic card edits retain the host marker, Duplicate remains separate, rename detaches, and normal same-name reimport with a new `create_date` does not inherit the old Scope. Detached candidates with the same URL do not block another Character's Server Remote access. A missing `create_date` disables Character binding but permits transient Server Remote access. Manual Rebind remains explicit. A raw filesystem replacement reproducing both filename and `create_date` cannot be distinguished using host metadata alone. |
| Failure boundary | An effective Binding with missing Original fails visibly without automatic source fetch. When Localization resolve is unavailable, the image fails conservatively; the user can explicitly request one Server source fetch. A failed Server fetch does not become a Localization error or browser fetch. Cross-account isolation, Network policy/MIME/size checks, Media Original and Catalog CAS are exercised in the existing module tests. |

Run `npm run check` in **both** repositories against the final candidate commits. The frontend check builds the installable JSON. The Server check includes the localization, Media, Network, protocol and privacy gates. These checks do not prove WebView behavior, actual Regex output, Network requests, mobile layout or installed-host durability.

## Minimum installed-host supplement

Use a disposable character with your real `<img>name</img>` Regex rule, one ordinary image URL and one animated GIF URL accepted by the existing administrator Network policy. Use the same authenticated ST user on desktop and phone. Keep DevTools Network open on desktop with cache disabled; filter by the image origin and the Toolbox Server routes. Do not put actual URLs, credentials, cookies or user data in public logs.

1. **Routing and streaming.** In the desktop browser, enable Routing under Server settings and confirm the text says it applies to the current browser. Render the Regex character's old and new messages, including a streaming reply whose partial and final text include images. GIF must animate. Inspect Network: before and during hydration there are Server requests and **no image-origin request**. Reload, switch chats, and reload the plugin once; images continue to work. Turn Routing off, rerender, and confirm the normal source request returns. Turn it on again for the following steps. A phone has its own switch; enabling it there should use Server too.
2. **Localize and update across devices.** Save the ordinary image and GIF to Server from the disposable character; check both live duplicates of a locator update together. Reload on desktop, then enable Routing on phone and open the same character: both devices should read the localized Original. With the source unavailable or temporarily disallowed in the private policy, the saved GIF should still animate. Update a Binding explicitly and verify the new Original appears on both devices after refresh. Cause one safe import failure or stale revision on test data; the previous Binding must remain usable. Unlocalize and confirm Server Remote access resumes when the source is available. The Catalog persists through a Server restart.
3. **Failure and identity.** For a disposable localized asset only, make its MediaRef unavailable using a controlled test operation; the image must show a broken state and cause no source-origin or automatic Server Remote request. Restore/replace the test asset as needed. Stop Server or disable Localization and reload: show a visible failure, with no automatic browser direct fetch; if offered, “经 Server 使用源图一次” runs only when explicitly pressed. Edit the card normally and confirm Binding survives. Duplicate, delete/reimport under the same filename, and rename: no old Binding is auto-attached to the new identity; Detached remains visible and only explicit manual Rebind restores it. A new character sharing the URL still loads through Server Remote access.

Record the installed ST version, frontend and Server commit IDs, browser/device, pass/fail per step and any exception. If a controlled Broken MediaRef scenario cannot be arranged safely, mark that specific installed-host negative case unverified; automated evidence remains distinct. A single ST user across devices tests sharing, not second-user isolation. Do not merge or release while a blocking result remains.
